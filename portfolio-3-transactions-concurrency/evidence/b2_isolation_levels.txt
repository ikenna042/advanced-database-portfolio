CREATE VIEW pg_temp.alpha AS
SELECT balance_kobo FROM wallets WHERE wallet_number = '1000000001';

=== B2.1  Dirty read: not possible in PostgreSQL, even at READ UNCOMMITTED ===
[A] begins a N1,000 transfer from Alpha and does not commit
BEGIN;
SELECT status FROM transfer('1000000001', '1000000002', 100000, 'b2-dirty');
  status   
-----------
 completed

SELECT * FROM pg_temp.alpha;
 balance_kobo 
--------------
      5750000

[B] reads Alpha at READ UNCOMMITTED
SELECT pg_temp.b('BEGIN ISOLATION LEVEL READ UNCOMMITTED');
   b   
-------
 BEGIN

SELECT pg_temp.b_value($$SELECT balance_kobo::text FROM wallets WHERE wallet_number = '1000000001'$$) AS b_sees;
 b_sees  
---------
 5850000

SELECT pg_temp.b('COMMIT');
   b    
--------
 COMMIT

B saw the committed balance, not A's uncommitted one. PostgreSQL runs READ UNCOMMITTED as READ COMMITTED.
ROLLBACK;

=== B2.6  The cost of REPEATABLE READ: writers must retry ===
BEGIN ISOLATION LEVEL REPEATABLE READ;
[A] reads Alpha's balance, which fixes its snapshot
SELECT * FROM pg_temp.alpha;
 balance_kobo 
--------------
      5450000

[B] sends N1,000 from Alpha and commits
SELECT pg_temp.b_value($$SELECT status FROM transfer('1000000001', '1000000002', 100000, 'b2-retry-b')$$) AS b_transfer;
 b_transfer 
------------
 completed

[A] now tries its own transfer from Alpha. transfer() locks Alpha's row, which changed
    after A's snapshot, so PostgreSQL raises SQLSTATE 40001 instead of using stale data:
SELECT status FROM transfer('1000000001', '1000000002', 100000, 'b2-retry-a');

      FOR UPDATE"
