CREATE VIEW pg_temp.balances AS
SELECT wallet_number, balance_kobo, version FROM wallets
 WHERE wallet_number IN ('1000000001', '1000000002', '2000000001') ORDER BY wallet_number;
SET deadlock_timeout = '5s';

=== B4.1  Deadlock: two transfers in opposite directions, locking in request order ===
Naive code locks the source wallet first, then the destination.
BEGIN;
[A] Alpha -> Bravo: locks Alpha
SELECT wallet_number FROM wallets WHERE wallet_number = '1000000001' FOR UPDATE;
 wallet_number 
---------------
 1000000001

[B] Bravo -> Alpha: locks Bravo
SELECT pg_temp.b('BEGIN');
   b   
-------
 BEGIN

SELECT pg_temp.b_value($$SELECT wallet_number::text FROM wallets WHERE wallet_number = '1000000002' FOR UPDATE$$) AS b_locked;
  b_locked  
------------
 1000000002

[B] now wants Alpha, which A holds, so B waits
SELECT pg_temp.b_start($$SELECT wallet_number::text FROM wallets WHERE wallet_number = '1000000001' FOR UPDATE$$);

  status

=== B4.4  Optimistic locking with the version column ===
Two support agents open Bravo's wallet on screen. Each change is written only if
the version is still the one the agent saw. Ledger entries also increase the version.
SELECT version AS seen_version FROM wallets WHERE wallet_number = '1000000002' 
SELECT wallet_number, status, version FROM wallets WHERE wallet_number = '1000000002';
 wallet_number | status | version 
---------------+--------+---------
 1000000002    | active |      15

SELECT set_config('kolaro.staff_id', (SELECT staff_id::TEXT FROM staff WHERE role = 'compliance'), FALSE) 
[A] compliance freezes the wallet after a fraud report
UPDATE wallets SET status = 'frozen', version = version + 1
 WHERE wallet_number = '1000000002' AND version = 15;
[B] support, still looking at the old screen, tries to close the wallet at the customer's request
SELECT pg_temp.b(format($$UPDATE wallets SET status = 'closed', version = version + 1
                          WHERE wallet_number = '1000000002' AND version = %s$$, 15)) AS b_update;
 b_update 
----------
 UPDATE 0

UPDATE 0: B's version is stale, so nothing changed. B must reload and see that the wallet is frozen.
