== R2.3 Even the synchronous standby can serve a stale read ==

synchronous_commit = on (the default) waits until node2 has flushed the WAL, not until it
has applied it. With node2's replay paused, a commit on node1 still returns at once:

[node2] SELECT pg_wal_replay_pause()
     pg_wal_replay_pause 
    ---------------------
     


[node1] SELECT transfer_id, status FROM wallet.transfer('3100000001', '3100000002', 100000, 'r2-sync-flush')
     transfer_id |  status   
    -------------+-----------
            5325 | completed


[node2] SELECT wallet_number, balance_kobo FROM wallet.wallets WHERE wallet_number IN ('3100000001', '3100000002') ORDER BY 1
     wallet_number | balance_kobo 
    ---------------+--------------
     3100000001    |      4250000
     3100000002    |      5750000


synchronous_commit = remote_apply waits until node2 has applied it. The same kind of
transfer now waits. After 3 seconds node2's replay is resumed:

[node1] SELECT application_name, wait_event_type, wait_event, now() - xact_start AS waiting_for
             FROM pg_stat_activity WHERE wait_event = 'SyncRep'
