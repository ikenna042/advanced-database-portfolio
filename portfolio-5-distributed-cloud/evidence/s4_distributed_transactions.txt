co-locating it with wallets would keep a same-shard transfer on one worker.

PREPARE TRANSACTION asks each worker to make its part durable and promise it can commit.
Only when every worker has prepared does the coordinator send COMMIT PREPARED. Citus
records the decision in pg_dist_transaction, so if the coordinator fails in between, a
recovery process can finish or roll back the prepared transactions.

== S4.3 Atomicity across workers ==

UPDATE wallet.wallets SET balance_kobo = balance_kobo + 999999999999 WHERE wallet_id = 13;

COMMIT;

== S4.4 How many real transfers would span shards? ==

[coordinator] WITH oct AS MATERIALIZED (
       SELECT source_wallet_id, destination_wallet_id FROM wallet.transfers
        WHERE created_at >= '2026-10-01' AND created_at < '2026-11-01'),
     placed AS (
       SELECT s.shardid AS src_shard, d.shardid AS dst_shard, s.nodename AS src_node, d.nodename AS dst_node
         FROM oct
         JOIN wallet.wallet_placement s ON s.wallet_id = oct.source_wallet_id
         JOIN wallet.wallet_placement d ON d.wallet_id = oct.destination_wallet_id)
     SELECT count(*) AS october_transfers,
            round(100.0 * count(*) FILTER (WHERE src_shard = dst_shard) / count(*), 1) AS pct_same_shard,
            round(100.0 * count(*) FILTER (WHERE src_shard <> dst_shard AND src_node = dst_node) / count(*), 1) AS pct_same_worker,
            round(100.0 * count(*) FILTER (WHERE src_node <> dst_node) / count(*), 1) AS pct_different_workers
       FROM placed
     october_transfers | pct_same_shard | pct_same_worker | pct_different_workers 
    -------------------+----------------+-----------------+-----------------------
                130751 |            3.1 |            47.1 |                  49.9
